How long connections lasted
One row per peer, one column per pixel of time. Each mark is the messages exchanged in that slice — inbound above the line, outbound below — shaded by how many. Vertical ticks are connection events.

Every transaction reaches this node more than once. The peers that announce it first are doing the work; the rest arrive to find it already held, and the bytes they spent getting there were spent again.

Which peers told you first
A peer that has been connected longer wins more races simply by being there, so the rate beside the count is what makes two peers comparable. Wasted bytes are transactions this node already had when they arrived.
How late the other announcements were
Mostly not the network. Bitcoin Core holds announcements back on a Poisson timer averaging five seconds to inbound peers and two to outbound ones, so this is largely its own scheduling seen from the other side.
How long this node went without the transaction
From the first announcement by anyone to holding the transaction, so it includes Core's own request delay, not just the peer's response time.
